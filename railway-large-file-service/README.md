# سرویس آپلود فایل‌های بزرگ (Railway)

این سرویس دو تا فرآیند رو داخل یک کانتینر اجرا می‌کنه:

1. **`telegram-bot-api`** (نسخه خودمیزبانیِ رسمی API تلگرام) — سقف دانلود فایل رو از ۲۰MB به ۲۰۰۰MB می‌بره.
2. یه سرور کوچیک **Node/Express** که فایل رو از سرور محلی تلگرام می‌گیره و به‌صورت استریم (بدون بافر کامل در رم)
   با **Resumable Upload** به گوگل‌درایو کاربر می‌فرسته.

Worker اصلی (روی Cloudflare) وقتی فایلی بالای ۲۰ مگابایت برسه، درخواست رو با یک HTTP call به این سرویس
پاس می‌ده و فوراً جواب می‌گیره؛ آپلود واقعی در پس‌زمینه همینجا ادامه پیدا می‌کنه و نتیجه‌ی نهایی مستقیماً
با ویرایش همون پیام وضعیت به کاربر در تلگرام اطلاع داده می‌شه.

---

## ۱. گرفتن API ID و API Hash تلگرام

این جدا از `BOT_TOKEN` هست و برای اجرای `telegram-bot-api` لازمه:

1. به [my.telegram.org](https://my.telegram.org) برید و با شماره تلفن خودتون وارد شید.
2. روی **API development tools** بزنید.
3. یک اپلیکیشن جدید بسازید (اسم و توضیح دلخواه، پلتفرم رو می‌تونید "Server" بذارید).
4. `api_id` و `api_hash` رو نگه دارید.

## ۲. دیپلوی روی Railway

1. یک پروژه‌ی جدید در [Railway](https://railway.app) بسازید.
2. **Deploy from GitHub repo** رو انتخاب کنید و فقط پوشه‌ی `railway-large-file-service` رو
   به‌عنوان root directory سرویس معرفی کنید (در تنظیمات سرویس → Settings → Root Directory).
   Railway به‌صورت خودکار `Dockerfile` رو تشخیص می‌ده و می‌سازه.
3. در بخش **Variables** این مقادیر رو ست کنید:

   | نام | مقدار |
   |---|---|
   | `TELEGRAM_API_ID` | از مرحله‌ی قبل |
   | `TELEGRAM_API_HASH` | از مرحله‌ی قبل |
   | `SHARED_SECRET` | یک رشته‌ی تصادفی طولانی (مثلاً با `openssl rand -hex 24`) — باید دقیقاً با `RAILWAY_SHARED_SECRET` در Worker یکی باشه |
   | `PORT` | Railway خودش این رو تزریق می‌کنه، معمولاً نیازی به دستکاری نیست |

4. بعد از دیپلوی موفق، Railway یک دامنه‌ی عمومی می‌ده (چیزی شبیه
   `https://xxxxx.up.railway.app`) — از **Settings → Networking → Generate Domain** فعالش کنید.

## ۳. وصل کردن به Worker اصلی

در پروژه‌ی اصلی (`telegram-drive-bot`)، دو تا secret جدید ست کنید:

```bash
npx wrangler secret put RAILWAY_LARGE_FILE_URL
# مقدار: https://xxxxx.up.railway.app   (بدون اسلش انتهایی)

npx wrangler secret put RAILWAY_SHARED_SECRET
# مقدار: همون رشته‌ای که در Railway به‌عنوان SHARED_SECRET گذاشتید
```

سپس Worker رو دوباره دیپلوی کنید:

```bash
npm run deploy
```

## ۴. تست

یه فایل بالای ۲۰ مگابایت به ربات بفرستید. باید پیام «فایل بزرگه، در پس‌زمینه آپلود می‌شه» رو ببینید،
و بعد از چند ثانیه تا چند دقیقه (بسته به حجم و سرعت اینترنت) پیام نهایی با لینک گوگل‌درایو بیاد.

برای دیدن لاگ‌های زنده و بررسی خطاها، از تب **Deployments → View Logs** در داشبورد Railway استفاده کنید.

## نکات و محدودیت‌ها

- **توکن گوگل کوتاه‌مدته:** access token گوگل که Worker به این سرویس می‌ده حدود ۱ ساعت اعتبار داره.
  برای فایل‌های خیلی حجیم روی اینترنت خیلی کند، در تئوری ممکنه قبل از اتمام آپلود منقضی بشه. اگه این
  مشکل پیش اومد، بگو تا مکانیزم رفرش خودکار توکن رو هم به سرویس اضافه کنم.
- **پایداری:** اگه پروسه‌ی `telegram-bot-api` داخل کانتینر کرش کنه، کل کانتینر خودش رو ری‌استارت
  نمی‌کنه مگر Railway health-check رو fail بده. برای شروع/تست کافیه؛ برای پروداکشن واقعی بهتره یه
  process manager (مثل `tini` + health endpoint دقیق‌تر) اضافه بشه.
- **هزینه:** این سرویس تقریباً همیشه idle نیست (چون `telegram-bot-api` مدام در پس‌زمینه اجراست)،
  پس اعتبار ۵ دلاری رایگان Railway احتمالاً ظرف چند هفته تموم می‌شه؛ در پنل Railway می‌تونید مصرف
  رو زیر نظر داشته باشید.
